# 勾稽助手

把**明细表 → 科目余额表 → 试算表/报表**三级勾起来，逐项对账，把差异、未映射科目、单边项目一次列全。

双击 `index.html` 就能用。不用装软件、不联网，客户数据不出你这台电脑。

---

## 为什么需要它

科目余额表到报表之间隔着一层「科目 → 报表项目」的归集。这层归集在 Excel 里靠手拉 SUMIF 或者透视表做，最容易出三种错：

1. **漏科目**——某个科目没被任何一个 SUMIF 覆盖，金额凭空消失
2. **重复计**——上级科目和明细科目同时被加了，金额翻倍
3. **方向反**——累计折旧、减值准备该减的加成了加

这三种错在表上都"看起来正常"，只有跟报表对不上时才会暴露，而且往往查很久。这个工具把这三件事变成可检查的：**每个报表项目都能追到构成它的科目，没归上的科目单独列出来。**

---

## 三步用法

### 1 选科目余额表

客户导出的科目余额表、余额明细表都行（金蝶、用友、SAP 导出的结构都能认）。

工具会自动找表头、认出「期初余额 / 期间发生额 / 累计发生额 / 期末余额」四组金额，以及每组的方向列。

选完会显示一行结论：

> 认出 341 个科目（末级 330 个，只算末级）；借方合计 883,535,917.24，贷方 6,010,005,757.15，差 -5,126,469,839.91

**借贷不平不拦你**，只是告诉你。因为很多导出只含资产负债类、不含损益类，不平是正常的——但你要知道它不平。

### 2 选试算表 / 报表

认「项目 | 金额」这种竖清单，也认「资产在左、负债在右」并排写的试算表（事务所模板常见）。并排的会自动切成两栏，分别选。

金额列也能选：审计前 / 调整后 / 审定数。

### 3 明细表（可选）

再选一张明细表，就多一级：**明细表合计 ↔ 科目余额表该项目汇总**。

明细表通常是「一个报表项目一张工作表」，而且一列一个口径（合并数、本公司、抵消……）。工具会把每列的表头和合计都列出来，由你指定取哪一列——它不替你猜哪列是金额。

### 4 看差异

四类结果，按重要性排：

| 看什么 | 为什么先看它 |
|---|---|
| **未映射科目** | 有余额的科目没归到任何项目，汇总一定对不上。先解决这个 |
| **明细表差异** | 明细表合计和科目余额表对不上，多半是底稿抄错或漏行 |
| **差异项目** | 科目汇总 vs 报表，差多少，由哪几个科目构成 |
| **单边项目** | 一边有一边没有，通常是项目名写法不同 |
| **对上的项目** | 折起来，需要时再点开 |

点「生成勾稽底稿」出一份 xlsx：勾稽表 / 未映射科目 / 单边项目 / 说明，可以直接归进底稿。

## 未映射的科目怎么办

工具**不猜**科目归属。认不出的（比如客户自定义的 `1526`、`2601`）会列在「未映射科目」里，让你手工指定一次：

```
1526=其他非流动资产
2601=长期借款
```

指定过的记在浏览器本地，下次遇到同一个编码自动归位。

这是故意的：猜错了会静悄悄地把金额挪到错误的报表项目上，比不猜危险得多。

## 内置了什么

- 100+ 个《企业会计准则》标准科目编码的归属（1001 库存现金 → 货币资金，1122 应收账款 → 应收账款……）
- 备抵科目按负向计入（1602 累计折旧、1231 坏账准备、4201 库存股）
- 末级科目判定：上下级同时存在时只汇总末级，不重复计
- 恒等式校验：`期初 + 本期借方 - 本期贷方 = 期末`，不成立的行单独报出来——这比"借贷合计不平"更能定位到具体哪一行坏了

---

## 做不到的

说实话比说漂亮话有用：

- **不判断对错**。它只告诉你两边差多少，差得对不对要你自己看。
- **不认欧洲小数**。`1.234,56` 会读成 1.23。国内导出的表不会这样。
- **不处理合并抵销**。合并报表的内部往来抵销不在范围内。
- **不认图片形式的表**。扫描件、截图里的表读不了。
- **明细表取哪一列要你自己指定**。合并数/本公司/抵消各占一列，选错了差异会很大——这是故意的，替你猜更麻烦。
- **不判断合并抵销对不对**。它只告诉你两边差多少。
- **科目编码必须是标准四位数开头**。编码里取不出四位数字的科目会被归到「未映射」，不会硬凑。

## 测试

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File test\run-all.ps1
```

```
core       全部通过：83 项断言
detail     明细表勾稽全部通过：27 项断言
limits     异常输入全部通过：41 项断言
export     导出装配全部通过：34 项断言
ui-smoke   界面冒烟全部通过：18 项断言
real       跳过：没有设置 GOUJI_REAL_FILES
全部通过，共 203 项断言
```

- `core.test.js` —— 金额、科目映射、汇总、比对、未映射、恒等式、两级表头解析、并排试算表切块
- `detail.test.js` —— 明细表合计数取法、三级比对、列的选择
- `limits.test.js` —— 空表、怪编码、坏金额、重复科目、脏数据导出
- `export.test.js` —— 底稿四张表的结构、金额格式、文件名规则
- `ui-smoke.test.js` —— 用假 DOM 加载真实的 `app.js`，点「示例数据」跑完整链路
- `real.test.js` —— 拿本机真实底稿跑结构回归。客户路径通过环境变量给，不进仓库：

```powershell
$env:GOUJI_REAL_FILES = "余额表.xlsx;明细表.xlsx;试算表.xls"
```

不设置就自动跳过，别人 clone 下来不会红。

核心逻辑（`core.js`）是纯函数，不碰 DOM，所以能直接在 Node 里测。
